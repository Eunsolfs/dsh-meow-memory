# 常见问题（0.35 fork）

装不上、检索不准、行为不符合预期时先查这里。

---

## 安装

### 这个 fork 从哪里装？

**本 fork 没有发布到 npm registry。** 推荐两条路：

1. **本地目录 / tarball**：先在本仓库 `npm install && npm run build`，再 GUI **Plugins → Add plugin** 填仓库绝对路径或 `npm pack` 生成的 `.tgz` 绝对路径；
2. **手动装进 profile**：复制/junction 到 `~/.dsh/profiles/<profile>/node_modules/meow-memory`，并加进 `dsh.profile.bundles`。

> `npm install meow-memory` 装到的是**上游 0.31.1**，不是本仓库。想用本 fork 的加固，只能从本地装。

### 为什么不能用 `dsh plugin add github:...`？

`github:` / git 依赖会安装 **devDependencies 并执行 `prepare`（esbuild 构建）**，需要 GitHub 可达、pnpm 允许构建脚本（≥10 默认阻止，要手工加 `allowBuilds`）、`@deepseek-ai/dsh-*` devDep 能解析。任何一步失败都会回滚。除非你就是要验证构建链，否则用本地目录/tarball。

### 首次 `dsh plugin add` 失败，提示 `allowBuilds`

pnpm ≥10 默认阻止安装期构建脚本。按提示把输出的键加进 profile 的 `pnpm-workspace.yaml` 后重跑。**只有 github/git 或从源码目录安装才需要构建**；预构建 tarball 不需要。

### Node 版本要求

`node:sqlite` 是运行时依赖：**Node ≥22.13 默认可用**；22.5–22.12 需 `--experimental-sqlite`。无原生模块。

### 关于 `@deepseek-ai/schemastery` peer 依赖

声明为 **peerDependency** 且构建时 external：配置 schema 必须与运行中的 DSH 宿主用同一个构造器。走 profile bundles / dsh 插件通道安装时由宿主解析，无需操作。若设置页与插件对 schema 行为不一致，优先改用 dsh 插件通道。

### 卸载会删掉我的记忆吗？

**不会。** 卸载只移除插件代码，不删数据。需要手动清理：

```
<工作区>/.dsh-meow/                       # 工作区库 memory.db、sessions/、.owner.json、.gitignore
~/.dsh-meow/                              # 或你配置的 homeDir：global/memory.db（用户级全局库）、logs、window-index
$DSH_HOME/storages/meow-memory*           # install-id、prompt 覆盖层、memory_home 切换指针
```

### 从上游 0.31 升级后记忆不生效 / 提示"库未受信"？

旧 `memory.db` 没有 `.owner.json` 标记，本 fork 首次运行会判为 **foreign/untrusted**（**即使是空的旧库也算"已存在"**）：库不会被打开（不升级/不建索引/不迁移/不读），内容不注入，记忆工具读写与 dream/反思被拒，并显示一次 untrusted-store 提示。要保留旧记忆：

- 在 profile 配置里设 `security.trustWorkspaceMemory: true` 后重载插件（确认是自己创建的库再开）；或
- 删除/改名旧库重新开始（先备份，删除不可恢复）。

> **0.33 升级补充**：工作区库受信后，首个会话会把原有 soul/user/全局 rules **迁移进用户级全局库**（工作区原行归档，可恢复）。如果全局库本身缺失/未受信，插件自动退回 0.32 单工作区行为（不报错）；全局库没有 `trustWorkspaceMemory` 配置信任档，他机复制来的全局目录判 foreign。

## 成本与自动行为

### 为什么我没让它记东西，它也在花 token？

默认配置下插件会自动做三件事：**每次请求挂静态手册/工具描述（≈6.7k tokens，中文包实测；英文 ≈6.3k）**、**会话首轮注入快照**、**满足条件时自动 dream/反思（全上下文请求）**。这是记忆自动化的固有成本，不随"有没有手动调用工具"变化。

完整清单与上限见 [README 的成本章节](../README.md#装之前先读它会自动花-token)；关掉自动部分：

```yaml
config:
  reflect: false
  dream:
    enabled: false
```

或单窗口用会话行「…」菜单 → **记忆参与** 关自动注入/自动整理。

### 为什么 dream 没跑 / 反思没触发？

0.32 的自动整理是**默认有界**的，跳过条件（全部满足才跑）：

| 可能原因 | 说明 |
|---|---|
| 窗口未空闲够 | 空闲 ≥ `dream.idleMinutes`（默认 180 分钟）才进入允许状态 |
| 处在峰时抑制 | 默认北京时间 09:00–12:00、14:00–18:00 及各自前 15 分钟不触发 |
| **窗口没有 live agent** | 0.32 起自动 dream 不再 `agents.resume()` 复活裸 agent（#49），只在有活窗口时跑 |
| 上下文太大 | 估算超过 `budget.dreamMaxContextTokens`（默认 40000）跳过 |
| 今天已整理过 | `budget.dreamMaxPerWindowPerDay` 默认 1 次/窗口/天 |
| **进程级全局额度用完** | `budget.dreamMaxPerDayTotal` 默认 12 次/天（进程级滚动 24h，重启清零）；`0` = 关闭自动 dream |
| 整理中途上下文涨太大 | 后续轮次会重新估算，超 `dreamMaxContextTokens` 则提前收尾（未封存，之后可再 dream） |
| 隔离 dream 不可用 | `dream.isolated: true` 但宿主的 `subagents` 服务/`spawn` provider（需 `inheritsParentContext=false`）缺失 → 记一次日志后回退主 agent dream |
| 隔离 dream 失败/超时 | 子会话超时/出错会释放租约、下轮重试；连续 3 次失败按封存止损（可手动 `/dream`） |
| 该窗口被跳过 | 会话行「…」菜单可恢复 |
| 窗口太旧/已归档 | 无 live agent 且超过 24h 的旧窗口、已归档会话不处理 |
| 最后发言早于上次 dream | 只有最后发言晚于上次 dream 的窗口才整理 |

反思另有 `budget.reflectMinIntervalMinutes`（默认 20 分钟）、`budget.reflectMaxPerDay`（默认 6/窗口/天）与进程级 `budget.reflectMaxPerDayTotal`（默认 24/天，重启清零）限制。`security.debugLogs: true` 后日志会写明跳过原因。

### 怎么立刻整理，不等空闲？

输入框敲 `/dream`（与 `memory_dream` 工具同语义，**不受峰时抑制、每日频次、live-agent 与上下文大小闸限制**——手动 = 明确意愿）。它按**完整会话上下文**连跑最多 3 轮（atomic / topic / 项目总结）；上下文很大时先 `/compact` 再 dream。**手动永远走主 agent 路径**（隔离模式只作用于自动 dream）。已有整理在进行中会明确提示，不会重复启动。

### 开了 `dream.isolated` 后自动 dream 为什么在主会话里看不到？

这是 0.34 的隔离 dream（默认关）：自动 dream 在 **spawn 空上下文子会话**里执行，主会话没有 model-visible 的 dream 轮（只有 log-only catalog 事实），所以**主会话上下文 0 增长**；子会话 token 仍计费，子会话写入的条目会被归到父窗口后封存。代价：子会话只拿到「dream prompt + 最近对话 digest + 条目清单」（不含工具结果/插件通知），**整理质量低于主上下文路径**；且**隔离 dream 无法从 UI 中止**（只能等完成/超时/失败）。子会话继承父会话 agent preset，`memory_*` 可见性取决于该 preset；`isolatedArchiveChild` 在子会话 settle 后归档（成功/失败都会归档，留明文副本）。`subagents`/`spawn` 不可用时自动回退主 agent dream。

### 开了 `dream.isolated` 却没有整理？

**0.34.0 有 maxDepth 兼容 bug**：它向 spawn 传 `maxDepth: 0`，DSH 0.2.1 把 `maxDepth` 读成"子会话自身允许深度"并拒绝启动（`SubagentDepthError: subagent depth 1 exceeds maxDepth 0`），隔离 dream 完全不跑——请升级到 **0.34.1**（不再传 `maxDepth`）。若子会话启动仍被拒（深度/容量/鉴权等），0.34.1 会在同一轮回退主窗口 dream（日志 `isolated-dream rejection -> main-dream fallback`）；若没有任何整理，打开 `security.debugLogs` 看 `isolated-dream` 相关日志。

## 检索与命中

### 为什么第一条消息没有关键词命中？

**首轮不跑关键词命中**（从第二轮起）。首轮只注入长期记忆快照，这是刻意设计——详见[设计说明](设计说明.md)。

### 检索命中率低 / 命中不到

按可能性排序：

1. **`promptLang` 没显式配置**。它影响模型写条目用的语言——关键词按条目语言提取。首次使用请显式配置；值逐字匹配子目录名，填不存在名字（如 `pt`）会静默落回中文包。
2. **命中基于关键词而非全文**，关键词质量差就召回不到。用 `memory_update` 的 `keywords` 修正，或 `memory_list` 找到条目后重写。0.32 起 `minScore`（默认 0.35）会挡掉低分候选；调高更安静、调低更吵；0.33 的 fuzzy 补分能救回词形/词边界类变体（不是同义改写）；0.35 可选语义检索（默认关）能覆盖一部分同义改写，但只是 floor、不保证质量（见下一条）。
3. **`hit_count` 反馈需要时间**：0.32 起命中次数参与排序，但不是魔法——一条从没被命中过的条目不会自动变准。
4. **`pt-br` 没有葡语词干/停用词归一化**，葡语召回弱于英语，这是已知限制。

### 语义检索（0.35）怎么开？为什么没效果 / 会发什么数据？

0.35 起可选 `retrieval.semantic`，**默认关 = 零网络**。开启需要：`enabled: true` + 非空 `baseUrl`（OpenAI-compatible，如本地 Ollama `http://127.0.0.1:11434/v1`）+ `model`。要点：

- **不是本地模型**：插件不打包 embedding 模型，必须自备端点；默认变量 `MEOW_MEMORY_EMBEDDING_KEY` 未设置时**无 key 请求**（适配本地服务），只有自定义 `apiKeyEnv` 且变量缺失才视为未配置、不请求。
- **隐私**：开启后**记忆正文/标题/关键词**（写入与回填）和**用户消息/查询文本**会发到你配置的端点；默认关不发送。
- **效果**：只是 cosine **floor**（0.25 噪声地板，低于按 0；负/零按 0），不做 rerank，可能放进弱匹配；`memory_search explain=true` 可看 `semantic` 分项。
- **老记忆**：启用后插件 apply 会后台回填（全局库 + 各可信工作区，≤50 行/层；失败下次启动重试），所以历史条目也会逐步有向量。
- **失败**：超时（默认 5s）/网络错误/非 2xx 一律静默回退纯词法，不阻塞注入/检索/写入。
- **换模型**：已存向量是模型特定的，换模型/维度会让旧向量失效（按 0 处理），需重写条目或清掉重新回填。
- **设置页不暴露** `retrieval.semantic`，只能改 profile patch；改完热重载/重启插件生效。

`memory_search` 返回检索元数据视图（归属 + id + 时间 + 关键词 + 截断正文）；要看完整原文用 `memory_read`，要看项目全貌用 `memory_project`，要看全库条目清单用 `memory_list`。

### 用户闲聊时命中了别的项目

未锚定时命中只搜全局。`memory_remember/search/update/project` 带 project 参数即锚定该会话的当前项目。

### 全局记忆该填什么？

全局适用的信息 project 填**全局标记**（当前语言包 `labels.md` 的 `project.global`：中文包「全局」，英文/葡语包 `global`）。同时适用多个项目用英文逗号分隔（如 `"dsh, femo"`）。

## 安全与信任

### 我的记忆会进 git 吗？

默认不会：插件创建记忆目录时写 `<记忆目录>/.gitignore`（内容 `*`，目录自忽略）；已存在但缺 `*` 行时也会追加一行（防 `!*` 重新包含），`git add .` 不会提交 `memory.db`。但**不加密**，别把密钥写进记忆；`.gitignore` 只挡 git，不挡备份/同步盘。

### 为什么我的记忆库不生效/提示"未受信"？

工作区里已存在一个 `.dsh-meow/memory.db`，而它**没有有效 `.owner.json` 标记**（不是本插件在本次安装里创建的库）——**不论这个库是不是空的**：0.32 判为 untrusted。库不会被打开（不升级/不建索引/不迁移/不读），其内容不注入，且**所有记忆工具（读/写）、dream 与反思都会被拒绝**并提示未受信。这是防 #64-1（克隆来的仓库往 `.dsh-meow/` 塞毒记忆），也防"预置空库 + trigger"在写入时投毒。

有效标记要求：`schema=1`、`installId` 等于本机随机安装 id、`workspace` 与当前路径一致。确认库是你自己的：在配置里设 `security.trustWorkspaceMemory: true` 并重载；或删/改名该文件后重建。

> **0.33 全局库**：`<homeDir>/global/memory.db` 也有同样信任闸（`.owner.json`，`workspace: ''`）。全局库 foreign 时不会报错，而是**自动退回 0.32 单工作区行为**（soul/user/全局 rules 走工作区库）；它没有 `trustWorkspaceMemory` 配置信任档。

### 旧 `PROJECT.md` 会不会自动迁移？

**0.32 起不会**（`autoMigrate` 默认 `false`）。需要时显式打开并确认工作区可信——否则工作区里来路不明的 `PROJECT.md` 会零交互进入记忆。

### 为什么 `memory_home` 不让我切目录了？

0.32 起默认只读（`security.allowHomeSwitch: false`）：该工具模型可直接调用，搬动目录会改变日志 / window-index / migrate 状态等实例数据的落点，模型不该有这种文件系统副作用（#64-2；prompt 覆盖层已改为固定路径，不受目录切换影响）。需要切换就让用户在配置里显式打开。

### 记忆存哪里（两层）？换工作区还记得我吗？

0.33 起是两层：

- **用户级全局库**：`<homeDir>/global/memory.db`（默认 `~/.dsh-meow/global/memory.db`），存 `soul` / `user` / 全局 `rules` —— **跨工作区共享**；换工作区后这些记忆仍在。
- **工作区库**：`<工作区>/<projectDir>/memory.db`（`projectDir` 默认 `.dsh-meow`），存 `project` / `fact` / `lesson` / `topic` / 项目 rules —— 换工作区 = 新的项目记忆。
- 会话级留痕：`<工作区>/.dsh-meow/sessions/<id>.json`
- 两个库的信任标记：各自目录下的 `.owner.json`（全局库 `workspace: ''`）。
- 实例级全局目录（含全局库、日志 / window-index / migrate 状态）：默认 `~/.dsh-meow`（**在 `DSH_HOME` 之外**），由 `homeDir` / `MEOW_MEMORY_HOME` 决定；`homeDir`/`memory_home` 切换会连全局库一起搬。
- prompt 实例覆盖层：`$DSH_HOME/storages/meow-memory/prompts/<lang>/<slot>.md`（固定；不随 `homeDir`/`memory_home` 切换）

> 首次升级到 0.33 时，每个工作区首个可信会话会把旧工作区里的 soul/user/全局 rules **迁进全局库并归档工作区原件**（可恢复）；`backup.enabled`（0.34 起）会同时备份工作区库与全局库（全局库为空/未受信时跳过、不会为备份建目录）。备份文件为各自目录下的 `memory.db.bak`。**0.35 语义**：启用后各表会懒加 nullable `embedding TEXT`（JSON 向量）列，向量随库/备份一起走；未启用则不加列、不写向量。

## 兼容性（0.2.1-rc.2）

### 支持哪些 DSH 版本？

本 fork **实测 DSH Desktop 0.2.1-rc.2**（Electron 44.7.0 / Node 24.21.0，Windows 11）：隔离实例加载成功、3 条路由鉴权 200/401、设置命名空间出现、无 apply 错误；0.34 带 `dream.isolated: true` 的 live load 只验证加载（0.34.0 子会话启动 bug 后由复审发现、0.34.1 修复）；0.35 另做 default / semantic-enabled 两种配置的 live load（均加载成功、无 apply 错误；**禁用语义时启动零 embedding 请求**，未写真实 home）。**没有测 0.1.x**，不再宣称"兼容 dsh 0.1.5"。

### 设置页保存了不生效？

0.2.x 的 settings 服务改版后插件走降级适配。设置页能渲染，但"改字段 → 保存 → 热重载 → 生效"未在本 fork 实测；最坏情况是显示但不落 apply。装完按 [README 自测清单](../README.md#自测清单)验一次；否则直接改 profile patch 配置。**0.35 的 `retrieval.semantic` 在设置页不出现**，只能走 profile patch。

### dream 之后工具变少 / 模型被切换？

- **#66（未修）**：一次 dream 后会话工具集可能锁在 9 个精简工具，**需重启 dsh**。插件侧没有工具过滤，疑似宿主后台轮次策略未还原；0.32 的自动 dream 已改走 live-agent 路径，但手动 dream 仍可能触发。
- **#71（未修）**：只有配置了 `delegate.model` 才可能触发，默认空值不触发。
- 出现以上信号先重启 dsh；持续复现请提 issue 并附 `security.debugLogs: true` 的日志。

### 客户端 UI（折叠条/月亮图标）不见了？

这些依赖 0.2.x `ChatSnapshot` 内部结构与 DOM 观察，宿主补丁更新可能静默失效。只影响外观，不影响记忆数据与工具。

## 扩展与语言

### 界面语言和 prompt 语言为什么不一样？

界面文案跟随 DSH 的「设置 → 通用 → 语言」（UI 层）；注入给模型的 prompt 按 `promptLang`（prompt 层）。两层互不影响。

### 怎么加一门界面语言 / prompt 语言？

界面：加字典文件 + `SUPPORTED_UI_LOCALES` 一行，见 [`src/i18n/README.md`](../src/i18n/README.md)。  
prompt：`src/prompts/<lang>/` 一个子目录 + `node scripts/check-lang.mjs <lang>` 全绿，见 [`src/prompts/README.md`](../src/prompts/README.md)。实例级覆盖放 `$DSH_HOME/storages/meow-memory/prompts/<lang>/<slot>.md`（固定路径，不随 `homeDir`/`memory_home` 切换）。
