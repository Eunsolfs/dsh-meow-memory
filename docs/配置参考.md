# 配置参考（0.35 fork）

所有字段均可选。两种改法：

- **配置文件**（profile patch / `cordis.patch.yml` 的 `config:`）——**0.32 新增的 `security` / `budget` / `retrieval` 三组字段（含 0.35 的 `retrieval.semantic`）只能这样改**；
- **DSH 设置页**的「喵记忆」标签页——覆盖 0.31 已有的字段（总开关、目录、命中、反思、dream、delegate、语言等），字段级保存、可单项恢复默认（恢复默认 = 回到本插件出厂默认，不受 patch 基线影响）。

改完均需**热重载或重启 meow-memory 插件**生效（配置在 apply 时解析一次）。

> 0.32 的加固思路：把默认自动行为从"无界"改成"有明确上限"，但不替用户关掉功能。0.33 起存储改为**用户级全局库 + 工作区库两层**（自动迁移 + 回退，无新增配置字段）；检索加了一层**离线混合词法补分**（无配置开关）。0.35 新增**可选语义检索** `retrieval.semantic`（默认关 = 零网络；开启后需自备 OpenAI-compatible `/embeddings` 端点）。想省钱/减少自动动作，见[如何关掉自动花费](#如何关掉自动花费)。

## 基础与目录

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 总开关。`false` 时注入、反思、工具全部停用 |
| `projectDir` | string | `.dsh-meow` | 记忆目录，**相对工作区**。库在 `<工作区>/<projectDir>/memory.db` |
| `homeDir` | string | `''`（=平台用户主目录） | **实例级全局目录**：`global/memory.db`（用户级全局记忆库）、日志 / window-index / migrate 状态。取值见下。**prompt 覆盖层不在这里**（见下方 `promptLang` 小节） |
| `disabledWorkspaces` | string[] | `[]` | 工作区停用名单，cwd 归一精确匹配；命中后读/整理/写全拒（含手动 `/dream`） |

**`homeDir` 的取值**：

| 值 | 落点 |
|---|---|
| `''` 或缺省 | 平台用户主目录（即 `~/.dsh-meow`） |
| `'default'` | 同上（显式标记） |
| `'dsh-storage'` | `<DSH home>/storages/meow-memory` |
| `'plugin-root'` | `<插件根>/storage` |
| 绝对路径 | 自定义目录 |

> 默认全局目录在 **`DSH_HOME` 之外**（`~/.dsh-meow`）。隔离的 `DSH_HOME` 也会写真实用户目录；想隔离就用 `homeDir` 或 `MEOW_MEMORY_HOME` 指到别处。

## 分层存储（0.33，无新增配置字段）

| 层 | 路径 | 存什么 |
|---|---|---|
| 用户级全局库 | `<activeHomeDir>/global/memory.db`（默认 `~/.dsh-meow/global/memory.db`） | `soul` / `user` / 全局 `rules`（跨工作区共享） |
| 工作区库 | `<工作区>/<projectDir>/memory.db` | `project` / `fact` / `lesson` / `topic` / 项目 `rules` |

- **写入路由**：`memory_remember` 写 `soul`/`user` 或全局 `rules` → 全局库；其余 → 工作区库。读类工具（read/update/forget/search/list/find_similar）两库并查、按 id 去重（同 id **active 优先于 archived**）；`memory_project` 只读工作区库。
- **自动迁移**：每个工作区首个**可信**会话把原有 soul/user/全局 rules 按原 id 复制进全局库，然后归档工作区原件（可恢复）。幂等标记在工作区库 `dream_meta`（`globalmigrated:v1:<dir>`）；foreign 工作区不迁移。
- **回退**：全局库缺失/未受信/不可用时自动退回 0.32 单工作区行为；全局库**没有** `trustWorkspaceMemory` 配置信任档（他机复制/同步来的全局目录判 foreign）。
- **注意**：全局库随 `homeDir` / `memory_home` 搬移（Windows 上先关连接再搬）；`backup.enabled` 会同时备份工作区库与全局库（全局库为空/未受信时跳过并保持不创建目录）。

## 安全闸

0.32 新增。改完需重载插件。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `security.trustWorkspaceMemory` | bool | `false` | 信任**已存在**的 `memory.db`（含空库/schema-only；本插件创建的不受影响）。`false` 时该库不被打开（不升级/不建索引/不迁移/不读），内容不注入，且**所有记忆工具（读/写）、dream 与反思都被拒绝**；会话内提示一次（`untrusted-store` prompt 槽位） |
| `security.allowHomeSwitch` | bool | `false` | 允许模型经 `memory_home` **切换**全局目录。`false` 时 `memory_home` 只读：返回当前目录、三个预设、开关状态，传 `target` 明确拒绝 |
| `security.autoGitignore` | bool | `true` | 创建记忆目录时写 `.gitignore`（内容 `*`，目录自忽略）；已存在但缺 `*` 行时**追加一行 `*`**（防 `!*` 重新包含） |
| `security.debugLogs` | bool | `false` | `perf.log` + settings/configEditor 诊断 dump 的总闸（也可用 `MEOW_MEMORY_DEBUG=1`）。**不是零日志**：`dream-debug.log` 默认仍写（最小信息、48h 清理、5MB 轮转），`apply-error.log` / `settings-register-error.log` 只在出错时写 |

**信任判定规则**（`src/db.ts`）：

- **只有 `memory.db` 文件根本不存在** → 创建 schema + `.owner.json` 标记 → **trusted（created）**；
- 库已存在且 `.owner.json` 有效：`schema=1`、`installId` 等于本机**随机安装 id**（`$DSH_HOME/storages/meow-memory/install-id`）、`workspace` 与当前工作区一致 → **trusted（marker）**；缺/错 `installId`、他机标记、被搬到他处的标记一律不可信；install-id 落盘失败时校验 **fail-closed**；
- **库已存在（哪怕空表/schema-only）且无有效标记** → 按 `trustWorkspaceMemory` 决定 `config-trusted` / **foreign**；foreign 库不会被正常聊天轮打开（只有只读探针），不升级/不建索引/不迁移/不读；
- 标记文件永远放在记忆目录里，不写工作区根。
- `workspace` 比较经 **realpath 归一**（junction / 映射盘 / subst 别名打开同一库不再误判 foreign；解析不了的别名仍 fail-closed）。
- 信任闸覆盖范围（0.32.1）：HTTP 数据路由（`GET /meow-memory/dreamed-sessions`、`GET/POST /meow-memory/skip-dreams`；POST 对 untrusted 返回 403）、会话窗口活动跟踪、启动期 window-index 恢复——都不会为记账去打开/升级 untrusted 库。

> 为什么默认不信任：工作区常是 `git clone` 来的仓库。旧版会把仓库自带的 `.dsh-meow/memory.db` / `PROJECT.md` 零交互当成"用户长期记忆"注入，形成持久的 prompt injection 通道（#64-1）。确认库是你自己的，再打开信任或删除重建。0.32 起 untrusted 库的记忆工具调用会被拒绝（不是"返回空结果"），避免模型把未受信数据当作可信上下文继续使用。
>
> **从上游 0.31 升级**：旧 `memory.db` 没有 `.owner.json`（**即使是空的旧库也算"已存在"**）→ 首次运行被判 foreign/untrusted（不注入、工具读写与 dream/反思被拒）。保留旧记忆请设 `security.trustWorkspaceMemory: true` 后重载，或删除/改名旧库重新开始。

## 注入 / 整理预算

0.32 新增。改完需重载插件。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `budget.snapshotMaxChars` | number 500–60000 | `6000` | 首轮长期记忆快照的字符预算；装不下的条目直接不注入（补 …） |
| `budget.hitMaxChars` | number 200–20000 | `1500` | 单条关键词命中注入的字符上限 |
| `budget.reinjectMaxChars` | number 500–60000 | `8000` | 会话压缩后重注入的总字符上限 |
| `budget.dreamMaxContextTokens` | number 4000–400000 | `40000` | 自动 dream / 反思前估算会话上下文（**CJK 感知近似**：中文 ≈1.7 字符/token、其余 ≈4）；超过则**跳过该次自动整理**（手动 `/dream` 不吃此闸）。dream 的**后续轮次会重新估算**，增长后超限则提前收尾（条目不封存，之后可再 dream） |
| `budget.dreamMaxPerWindowPerDay` | number 0–24 | `1` | 自动 dream 每窗口每天上限；`0` = 不自动触发 |
| `budget.dreamMaxPerDayTotal` | number 0–200 | `12` | **进程级全局**自动 dream 上限/天（滚动 24h；N 个窗口不再 = N 倍花费）；`0` = 关闭自动 dream。计数在进程生命周期内，**重启清零** |
| `budget.reflectMaxPerDay` | number 0–100 | `6` | **每个窗口（会话）**每天反思上限；`0` = 不自动反思 |
| `budget.reflectMaxPerDayTotal` | number 0–500 | `24` | **进程级全局**自动反思上限/天（滚动 24h，重启清零）；`0` = 关闭自动反思 |
| `budget.reflectMinIntervalMinutes` | number 0–1440 | `20` | 两次自动反思的最小间隔（分钟） |

> 预算字段是**字符数**不是 token 数：中文约 `chars / 2.2`、英文约 `chars / 4`。它们限制的是单次注入/单次整理的规模，不是每天总花费（每日上限由频次字段控制）。
>
> `memory_project` 工具输出另有独立封顶：`max(2000, budget.reinjectMaxChars)`（默认 **8000 字符**），超出截断补 `…`；它与压缩重注入共用段落构造，但这条上限只作用于工具输出。
>
> 两个 `*MaxPerDayTotal` 是**进程级**计数（滚动 24h），只在本进程生命周期内有效，**重启/热重载后清零**；每窗口/每会话的 `dreamMaxPerWindowPerDay` / `reflectMaxPerDay` 仍独立生效。手动 `/dream` / `memory_dream` 不占这些自动额度。

## 检索 / 遗忘

0.32 新增。改完需重载插件。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `retrieval.halfLifeDays` | number 1–3650 | `30` | 指数半衰的半衰期（天）。`recency = 0.05 + 0.95·exp(-ln2·ageDays/halfLifeDays)`；`importance ≥ 3` 保留 0.85 下限 |
| `retrieval.minScore` | number 0–1 | `0.35` | 关键词命中的最低分门槛；低于它的候选不注入 |
| `retrieval.hitBoost` | bool | `true` | 命中次数反馈：`×(1 + 0.15·ln(1+hit_count))`，上限 2.0 |
| `retrieval.importanceWeight` | bool | `true` | importance 参与排序：`×(0.85 + 0.05·importance)`（1→0.9，4→1.05） |
| `retrieval.semantic.enabled` | bool | `false` | **0.35**：语义检索总开关。`true` 且 `baseUrl`/`model` 非空才启用；默认关 = **零网络请求**，行为与 0.34 完全一致 |
| `retrieval.semantic.baseUrl` | string | `''` | OpenAI-compatible 端点 base（实际请求 `${baseUrl}/embeddings`，如 `http://127.0.0.1:11434/v1`） |
| `retrieval.semantic.model` | string | `''` | embedding 模型名（由端点提供；插件不打包模型） |
| `retrieval.semantic.apiKeyEnv` | string | `'MEOW_MEMORY_EMBEDDING_KEY'` | key 所在环境变量名。**默认变量名未设置时允许无 key 请求**（本地 Ollama/LM Studio）；只有自定义了变量名且该变量缺失才视为未配置、不请求。key 存在时发 `Authorization: Bearer $env` |
| `retrieval.semantic.timeoutMs` | number 200–60000 | `5000` | 单次 embedding 请求超时（毫秒）；超时/失败静默回退纯词法 |
| `retrieval.semantic.weight` | number 0–1 | `0.8` | 语义 floor 混合权重：`relevance = max(词法, fuzzy, cos·weight·importanceWeight)`；`0` = 语义补分不参与排序（**仍可能发 embedding 请求**；想完全离线请关 `enabled`） |

每消息命中的真实打分（**不是 BM25**）：关键词交集 × IDF × **查询覆盖率** × 指数近期权重 × importance 权重 × title 加成。`memory_search` 才是 BM25（BM25 × 近期权重）。

> **0.33 混合词法补分（fuzzy，无配置开关）**：字符 bigram Jaccard + 0.25×trigram Jaccard（NFKC、只留字母数字、CJK 无需分词），噪声地板 0.2。它只作为 BM25 弱命中时的 **floor**：`score = max(BM25, 0.55·fuzzy·recency·importance)`（每消息命中链路：`relevance = max(BM25 relevance, fuzzy)`），BM25 强命中时排序不变；`memory_search explain=true` 的 `explain` 会带可选 `fuzzy`。纯 BM25 仅是测试/内部选项（`SearchOptions.fuzzy = false`），不是用户配置项。

> 覆盖率从 0.32 起按**查询命中比例**计算（旧版是 `命中数/条目关键词数`，关键词写得越多分越低，反向惩罚）。阈值调高（如 0.5）会更安静但漏召回更多；调低会更吵。

> **0.35 可选语义检索（`retrieval.semantic`，默认关）**：启用后把 query 与条目 embedding 的**余弦相似度也只当 floor**，含 **0.25 噪声地板**（cos < 0.25 按 0，避免无关条目靠偶发小相似度混入；负/零相似度按 0）：`relevance = max(词法, fuzzy, cos·weight·importanceWeight)`，`memory_search` 再 × recency、`explain` 带 `semantic` 分项。**不做 rerank**，可能把弱匹配放进结果。数据流：启用时 `memory_remember`/`memory_update`（content/keywords 变化）写后内联补 embedding（受 `timeoutMs` 约束、失败静默）；插件 apply 后**后台回填**全局库（soul/user/rules）与每个可信工作区（project/fact/lesson/topic/rules）各层 ≤50 行，失败下次启动重试。embedding 存在各层新增的 nullable `embedding TEXT`（JSON）列，随库/备份一起走。**隐私**：启用后**记忆正文/标题/关键词**与**用户消息/查询文本**会发送到你配置的 `/embeddings` 端点；默认关 = 不发送。**换 embedding 模型会让已存向量失效**（维度/语义不匹配；不同维度直接按 0 处理）——需重写条目或清掉重新回填。端点不可用时静默降级为纯词法，不阻塞注入/检索/写入。设置页**不暴露**这组字段。

## dream（空闲整理）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `dream.enabled` | bool | `true` | 是否允许自动整理 |
| `dream.idleMinutes` | number ≥1 | `180` | 窗口空闲多少分钟后允许 dream |
| `dream.suppressWindows` | `{start,end}[]` | 09:00–12:00、14:00–18:00 | 抑制时段（按 `timeZone`），这些时段内不触发 |
| `dream.suppressLeadMinutes` | number 0–120 | `15` | 每个抑制时段开始前追加的不触发分钟数 |
| `dream.checkMinutes` | number ≥1 | `15` | 检查周期 |
| `dream.timeZone` | string | `Asia/Shanghai` | 抑制时段所用时区 |
| `dream.rulesReviewDays` | number ≥0 | `2` | 稳定 `rules` 的 `updated_at` 超过该天数则不进 dream 第 1 轮；`0` = 不过滤 |
| `dream.requireLiveAgent` | bool | `true` | 自动 dream 只跑有 live agent 的窗口，**绝不 `agents.resume()` 复活**（#49）。手动 `/dream` / `memory_dream` 不走此自动闸（手动调用本身就在活窗口里） |
| `dream.isolated` | bool | `false` | **0.34**：自动 dream 改在**隔离 spawn 子会话**执行——主会话没有 model-visible 的 dream 轮，**主会话上下文 0 增长**（子会话 token 仍计费）。默认关；手动 `/dream` / `memory_dream` **始终**走主 agent 路径。子会话继承父会话 agent preset（`memory_*` 可见性取决于该 preset） |
| `dream.isolatedProvider` | string | `'spawn'` | 子会话 provider；要求 `inheritsParentContext === false`（spawn 满足，fork 不满足）。服务/provider 不可用、或**子会话启动被拒（同步/异步，如深度/容量/鉴权）**时回退主 agent dream（异步拒绝日志 `isolated-dream rejection -> main-dream fallback`） |
| `dream.isolatedTimeoutMinutes` | number 1–120 | `20` | 隔离 dream 超时（分钟）：超时后 dispose 子会话、释放租约、下轮重试；连续失败按既有上限（3 次）封存 |
| `dream.isolatedMaxPromptChars` | number 2000–60000 | `20000` | 子会话单条 prompt 的字符上限（digest + 条目行）；超限从旧条目/项目/digest 头部裁剪 |
| `dream.isolatedArchiveChild` | bool | `true` | 子会话 **settle 后**归档（`workspaceRegistry.archiveSession`，best-effort；**成功/失败都会归档**，会留一份明文子会话副本） |

自动 dream 的完整前置条件（全部满足才跑）：`dream.enabled` → 窗口空闲 ≥ `idleMinutes` → 不在抑制时段 → 该窗口有 **live agent** → 估算上下文 ≤ `budget.dreamMaxContextTokens` → 当天次数 < `budget.dreamMaxPerWindowPerDay` → 进程级当天次数 < `budget.dreamMaxPerDayTotal`。后续轮次会重新估算上下文，超限则提前收尾（未封存，之后可再 dream）；dream 第 1/2 轮的条目清单按 **`updated_at` 最新**取（不是 `created_at`），近期被更新过的老条目不会被 60 条上限饿死。每个条件都有日志说明跳过原因（`security.debugLogs` 打开后更详细）。

**隔离路径（`dream.isolated: true`）**：主上下文大小闸 `dreamMaxContextTokens` **不生效**（子会话 prompt 由 `isolatedMaxPromptChars` 独立封顶），频次/冷却/峰时/进程级每日上限仍生效。子会话是**空上下文**（不继承主会话 transcript），但**继承父会话的 agent preset**，`memory_*` 工具可见性取决于该 preset 的工具集；拿到的是 dream prompt + 最近 user/assistant 文本与工具名 digest（不含工具结果/插件通知）+ 条目清单；成功收尾会把子会话写入的条目 `source_session` 归到父窗口（`adoptSessionEntries`）再封存，部分结果也保留；超时/失败/中止回退主 agent 路径。**隔离 dream 无法从 UI 中止**；`delegate.model` 也会用于隔离子会话；`isolatedArchiveChild` 在子会话 settle 后归档（成功/失败都会归档，留明文子会话副本）。

> **0.34.1 兼容修复**：0.34.0 曾向 spawn 传 `maxDepth: 0`，DSH 0.2.1 把它读成"子会话自身允许深度"并拒绝（`SubagentDepthError`），导致隔离 dream 完全不跑；0.34.1 不再传 `maxDepth`（宿主默认 1），且启动被拒时同一轮回退主 agent dream。

**手动 `/dream` / `memory_dream` 不过这些成本闸**（手动 = 明确意愿，代码里只有自动路径调用 `evaluateAutoDreamGate`）：按**完整会话上下文**连跑最多 3 轮（atomic / topic / 项目总结），不因"上下文过大"跳过，且**始终走主 agent**（隔离模式只作用于自动 dream）。上下文很大时请先用 `/compact` 压缩会话再 dream。

> `suppressWindows` 默认值来自上游（北京时间 09:00–12:00 / 14:00–18:00），是按 GLM 峰谷电价设的，不是 DeepSeek 的优惠时段。用哪家模型请按自己的价格窗口改。

## `promptLang`：prompt 与检索语言（重要）

`promptLang` 决定：①注入/反思/dream 文案的语言；②工具描述的语言。它同时影响模型写记忆条目用的语言——关键词按条目语言提取，**以你说话的语言为准**。

**首次使用请显式配置**：`'zh'`（默认）、`'en'`、`'pt-br'`。配置值就是 `src/prompts/` 的子目录名，**逐字匹配**：填一个不存在的名字（例如 `pt`）不会报错，而是**静默落回中文包**。

不设置时：运行时按 `zh` 跑，且插件生效后的第一条真实用户消息会注入「首次设置」引导任务（AI 判断用户语言并完成配置，每会话至多提醒一次）。

**检索侧**：BM25 分词语言无关（CJK bigram / 其他 Unicode 词）；`en` 模式额外启用英语停用词 + Porter 词干。**`pt-br` 没有葡语词干/停用词归一化**——葡语召回会比英语弱，这是已知限制。

**自定义 / 实例覆盖**：`$DSH_HOME/storages/meow-memory/prompts/<lang>/<slot>.md`（`$DSH_HOME` 缺省 `~/.dsh`；可只覆盖部分槽位）。该路径**固定**，不随 `homeDir` / `memory_home` / `MEOW_MEMORY_HOME` 切换，旧位置（全局目录下的 `prompts/`）不再读取——否则一次目录切换就能改写注入给模型的全部指令（#64-2）。

## 界面语言

插件界面文案（折叠横条、气泡、菜单、设置页）走独立的 UI 文案层，跟随 DSH 的「设置 → 通用 → 语言」：内置中文 / English / Português (Brasil)。与 `promptLang` 是两层、互不影响。老宿主无 locale 服务时自动降级为浏览器语言 + 内置字典，最终落 `zh`。

## 如何关掉自动花费

```yaml
config:
  reflect: false                 # 关自动反思
  dream:
    enabled: false               # 关自动 dream（/dream 与 memory_dream 手动仍可用）
  budget:
    dreamMaxPerWindowPerDay: 0   # 或只关自动 dream 频次（效果同 enabled:false 的自动部分）
    reflectMaxPerDay: 0          # 或只关自动反思频次
```

单个窗口：会话行「…」菜单 → **记忆参与** → 关闭「自动注入」/「自动整理」。  
想彻底不付 ≈6.7k 静态税，只能停用/卸载插件。
