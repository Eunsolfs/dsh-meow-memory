# 工具参考（0.35 fork）

meow-memory 注册 **10 个**记忆工具。分档：**读**（search / read / find_similar / project / list）、**写**（remember / update / forget / dream）、**目录**（home）。

> 工具描述与返回文案跟随 `promptLang` 语言包；下表的参数说明在英文/葡语语言包下会以对应语言出现。参数 schema 本身不随语言变化。
>
> 0.33 起是**两层存储**（用户级全局库 + 工作区库）；写路由、读合并与迁移见[分层存储与工具路由](#分层存储与工具路由033)。

---

## 工具速查

| 工具 | 档 | 用途 |
|---|---|---|
| `memory_remember` | 写 | 写入一条记忆：必填 content / project / keywords / importance；soul/user/全局 rules → 全局库，其余 → 工作区库 |
| `memory_search` | 读 | 混合词法检索（BM25 × 近期权重 + 字符 n-gram floor；支持 `explain`，含可选 `fuzzy`）；两库并查 |
| `memory_project` | 读 | 取回某项目的完整注入段落（项目全景；**只读工作区库**） |
| `memory_find_similar` | 读 | 查重与冲突检测；两库并查 |
| `memory_read` | 读 | 按 id 读取单条完整元数据；两库并查 |
| `memory_update` | 写 | 按 id 修正 status / importance / goal / keywords / content（写回所属库） |
| `memory_list` | 读 | **0.32 新增**：列条目元数据（无正文），两库合并去重，用于盘点与找 id |
| `memory_forget` | 写 | **0.32 新增**：按 id 归档 / 恢复 / 硬删除；两库并查 |
| `memory_dream` | 写 | 手动触发本窗口记忆整理（与 `/dream` 命令同语义；只整理工作区库） |
| `memory_home` | 目录 | 查看全局数据目录；**0.32 起默认只读**（0.33 切换会连全局库一起搬） |

> 另有 `/dream` 用户命令（输入框直接敲），与 `memory_dream` 同语义，不受峰时抑制。

## 分层存储与工具路由（0.33）

```
<activeHomeDir>/global/memory.db        ← 用户级：soul / user / rules(全局)
<workspace>/<projectDir>/memory.db      ← 工作区级：project / fact / lesson / topic / rules(项目)
```

| 操作 | 行为 |
|---|---|
| 写（`memory_remember`） | `level=soul` / `user`，或 `level=rules` 且 project 是全局标记 → **全局库**；其余 → **工作区库**。去重/合并只在目标库内进行 |
| 读 / 改 / 删 / 检索 / 列表 / 查重 | `memory_read` / `update` / `forget` / `search` / `list` / `find_similar` **两库并查**，按 id 去重；同 id **active 优先于 archived**。`update` / `forget` 写回条目所属的库 |
| 项目全景 | `memory_project` **只读工作区库** |
| 迁移 | 每个工作区首个**可信**会话把原有 soul/user/全局 rules 按原 id 复制进全局库，然后归档工作区原件（可恢复）；幂等标记 `globalmigrated:v1:<dir>` 写在工作区库 `dream_meta` |
| 回退 | 全局库缺失/未受信/不可用时自动退回 0.32 单库行为；全局库 foreign 时**没有** `trustWorkspaceMemory` 配置信任档 |
| 备份 | `backup.enabled`（0.34 起）同时备份工作区库与全局库（全局库为空/未受信时跳过、不会为备份建目录） |

> 迁移后如果全局库丢失：工作区原行仍是 archived，**不会自动回灌**；用 `memory_forget`（`mode:'restore'`）逐条恢复，或恢复全局目录的备份。

## `memory_remember` — 写入

必填 `content` / `project` / `keywords` / `importance`；**缺失会逐个报错并引导重填**，没有"自动提取关键词"回退。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `content` | string | — | 必填。记忆正文 |
| `project` | string | — | 必填。项目名；全局信息填全局标记；多项目用英文逗号分隔 |
| `keywords` | string[] | — | 必填。8–13 个检索关键词（命中基于关键词而非全文） |
| `importance` | integer | `1` | 必填。权重，参与命中排序 |
| `level` | enum | `fact` | `soul` / `user` / `project` / `fact` / `lesson` / `topic` / `rules` |
| `subcategory` | enum | — | 仅 `level=project`：`overview` / `structure` / `decisions` / `quotes` / `ops` / `todo` |
| `goal` | string | — | 目标句（`topic` 层用） |
| `corrected` | boolean | `false` | 是否属于纠正类记忆 |

**返回**：`ok` / `id` / `level` / `merged`（是否合并进已有条目）/ `keywords` / `project`。

**写入位置（0.33）**：`level=soul` / `user`，或 `level=rules` 且 project 是全局标记 → **用户级全局库**；其余 → **工作区库**。去重/合并只在目标库内进行。

**语义 embedding（0.35，可选）**：启用 `retrieval.semantic` 时，写入/合并成功后 **best-effort** 补该条 embedding（内联、受 `timeoutMs` 约束；失败不影响写入结果，后续 apply 的后台回填会补）。未启用时完全不发请求。**端点挂起时本次写入最多增加 `timeoutMs`（默认 5s）延迟**；只允许 https 或 loopback http（远程明文 http 直接回退词法、零请求）。

**去重的真实边界**：只有**同一层级**、正文 bigram **Jaccard ≥ 0.8**（近逐字相同）才自动合并；改写、近义重复、跨层重复都**不会**合并。合并会用新关键词覆盖旧关键词、取 `max(importance)`。

## `memory_search` — 检索

**BM25 × 近期权重 + 0.33 混合词法 floor + 0.35 可选语义 floor**（每条消息的关键词命中是另一套打分，见下）。默认 `k=10`：前 5 条按相关度取（不排除已见/本会话建立的），后 5 条从后续排名绕开已见补齐，最后按记忆时间戳（旧→新）重排。**两库并查**（全局库 + 工作区库），按 id 去重。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `query` | string | — | 必填。查询词 |
| `level` | string | — | 层级过滤，逗号多选 |
| `project` | string | — | 项目过滤，逗号多选（OR 语义） |
| `status` | string | — | 状态过滤，逗号多选（OR）：`active` / `archived` / `stale` / `all` |
| `days` | integer 1–3650 | — | 只搜最近 N 天创建的条目 |
| `k` | integer 1–50 | `10` | 返回条数上限 |
| `content_max` | integer 0–5000 | `300` | 单条内容截断长度，`0` = 全文 |
| `explain` | boolean | `false` | 每条命中附带分项得分 `explain`（bm25 原始分 / importance / recencyWeight / status；0.33 另有可选 `fuzzy`，0.35 启用语义时另有 `semantic`，以及启用时的 `importanceWeight` / `hitBoost`），用于排查召回；不改排序 |

**返回**：`note` + `hits[]`。每条 hit = 归属 + 完整 id + 相对时间 + 关键词列表 + 截断正文（`content_max`）。

> 浏览项目全貌请用 `memory_project`，不要用 search 拼。

> **0.33 混合词法补分**：字符 bigram Jaccard + 0.25×trigram Jaccard（噪声地板 0.2），只在 BM25 弱命中时作为 floor（`score = max(BM25, 0.55·fuzzy·recency·importance)`）；BM25 强命中排序不变。**不是语义/embedding 检索**，同义改写仍可能召回不到。无配置开关（纯 BM25 是测试/内部选项）。

> **0.35 可选语义 floor；0.35.1 传输/延迟修正**：`retrieval.semantic.enabled: true` 时本工具会给 `query` 取一次 embedding（失败/超时 → 回退纯词法），`relevance = max(词法, fuzzy, cos·weight·importanceWeight)`，cos **<0.25 按 0**（噪声地板），再 × recency；`explain=true` 会带 `semantic` 分项。**不做 rerank**，可能放进弱匹配。**只允许 https 或 loopback http**（远程明文 http 拒绝、零请求回退词法）；**端点挂起时本次调用最多增加 `timeoutMs`（默认 5s）延迟**（不抛错、仍返回词法结果；连接被拒快速失败）。启用后**查询文本会发往你配置的 `/embeddings` 端点**；默认关 = 零网络。详见[配置参考](配置参考.md)。

## `memory_project` — 项目全景

取回某项目的完整注入段落。`project` 参数**必填**。**只读工作区库**（用户级全局库的条目不在项目全景里）。

**输出规则**：

- 非 `todo` 子标签：`active` 条目全部（自动注入路径受注入预算控制；本工具按调用返回，但整段输出有独立封顶，见下）；
- `todo` 子标签：`active` 全部为「To do list：」+ `stale`（已完成）按 `updated_at` 取最近 5 条为「已完成：」；
- 组内按记忆时间戳旧 → 新；只拼 `content` 纯文本。

**输出上限**：整段文本最多 `max(2000, budget.reinjectMaxChars)` 字符（默认 **8000**），超出截断补 `…`（与压缩重注入共用段落构造，但这条上限只作用于本工具输出）。

**副作用**：调用非全局、非多项目参数时，会**锚定当前会话的 project**——之后的关键词命中跟进该项目；同时把该项目记入本会话"查阅过"清单，供压缩后重注入项目全景。

> 若工作区记忆库被判为 **untrusted**（见[配置参考](配置参考.md#安全闸)），本工具调用会被**拒绝**并提示未受信。

## `memory_find_similar` — 查重

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `id` | string | — | 必填。基准记忆 id |
| `k` | integer 1–20 | `5` | 返回相似条目数 |
| `content_max` | integer 0–5000 | `200` | 内容截断长度 |

返回按 bigram 余弦相似度排序的条目；只查其他会话建立的记忆，本会话已见（注入/检索过）的自动排除。**两库并查**（soul/user 之外同层去重）。

## `memory_read` — 读单条

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 完整 id 或前 12 位短 id |

返回单条完整元数据（keywords / status / importance / goal / 时间戳等）。**两库并查**；命中条目属于哪个库，后续 update/forget 就写回哪个库。

> 只由 `memory_read` 单条读取触发「查阅过」留痕；`memory_project` 全景不标记（第三轮项目总结会专门复查）。

## `memory_update` — 修正

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | string | 必填 |
| `content` | string | 改写正文 |
| `status` | enum | `active` / `archived` / `stale`（`stale`=完结，`archived`=作废/被替代） |
| `importance` | integer | 权重 |
| `goal` | string | 目标句 |
| `project` | string | 项目归属；空字符串 = 清空 |
| `keywords` | string[] | 手动修正关键词（不传/空数组 = 不更新） |

> **0.35 可选语义**：启用 `retrieval.semantic` 且 `content` / `keywords` 有变化时，更新成功后 best-effort 重算该条 embedding（内联、受 `timeoutMs` 约束；失败保留旧向量/不影响更新）。未启用时完全不发请求；**端点挂起时本次更新最多增加 `timeoutMs` 延迟**（只允许 https/loopback http，远程明文 http 直接回退）。

> 写路径的短 id 歧义会**报错并列出候选**（0.31.1 起），不再静默改错条目。`updated_at` 在 update 或 dream 封存时刷新；对外展示的时间戳一律是 `updated_at`。

## `memory_list` — 列条目（0.32 新增）

低 token 成本的盘点视图：**只返回元数据，不返回正文**（这是与 `memory_search` / `memory_read` 的关键区别）。**两库合并、按 id 去重**（同 id active 优先）。用于「我到底记了什么 / 找出要清理的 id」。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `level` | string | `all` | 层级，逗号多选：`soul`/`user`/`project`/`fact`/`lesson`/`topic`/`rules`；`all`=全部 |
| `project` | string | — | 项目名，逗号多选（OR）；全局/未标记天然包含 |
| `status` | enum | `active` | `active` / `stale` / `archived` / `all` |
| `limit` | integer 1–100 | `20` | 返回条数上限 |
| `offset` | integer ≥0 | `0` | 分页偏移 |

**返回**：`{ note, total, items[] }`；`item = { id, level, title, keywords, importance, status, project, updated_at }`。

> `title` 是展示用标题（由正文截断生成），不是独立字段。要看正文用 `memory_read`。

## `memory_forget` — 归档 / 恢复 / 删除（0.32 新增）

按 id 处理**一条**记忆。默认是**可恢复的归档**；硬删除必须显式确认。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `id` | string | — | 必填。完整 id 或前 12 位短 id |
| `mode` | enum | `archive` | `archive`=归档（可恢复）/ `restore`=取消归档回 `active` / `delete`=永久硬删除 |
| `confirm` | boolean | — | `mode=delete` 时**必须传 `true`**，否则拒绝执行；其他模式忽略 |

**返回**：`{ note, id }`。

**副作用**：

- `archive`：`status` 改为 `archived`，条目不再参与关键词命中/injection，数据仍在库中，可 `restore`；
- `restore`：`archived` → `active`；
- `delete`：从表里物理删除，**不可恢复**（没有回收站；`backup.enabled` 的 `.bak` 是你唯一的退路）。

> 批量清理请用 `memory_list` 拿到 id 后多次调用；不提供按条件批量删除，避免模型一次清空记忆库。

## `memory_dream` — 手动整理

无参数（整理范围固定为本窗口）。与 `/dream` 命令同语义：**手动 = 明确意愿，不吃自动成本闸**——不受峰时抑制、每日频次与上下文大小闸限制（手动调用本身就在活窗口里），按**完整会话上下文**连跑最多 3 轮（atomic / topic / 项目总结）。上下文很大时请先 `/compact` 再 dream。

0.34 的隔离模式（`dream.isolated: true`，**0.34.1 起在 0.2.1 上可用**；0.34.0 因向 spawn 传 `maxDepth: 0` 被宿主拒绝）**只作用于自动 dream**：自动 dream 在 spawn 子会话里执行、主会话 0 增长且无 model-visible dream 轮；**手动 `/dream` / `memory_dream` 始终走主 agent 路径**（可看可中止）。子会话继承父 agent preset（`memory_*` 可见性取决于它），启动被拒会同一轮回退主窗口 dream；`isolatedArchiveChild` 在 settle 后归档子会话（成功/失败都会归档）。隔离 dream 本身**无法从 UI 中止**，且 digest 质量低于主上下文路径。

> 已有整理在进行中会明确提示，不会重复启动。dream 仅整理工作区库（全局条目靠工具/反思维护）。

## `memory_home` — 全局数据目录（0.32 起默认只读）

查看实例级全局数据目录（日志 / window-index / migrate 状态；prompt 覆盖层不在这里，固定解析自 `$DSH_HOME/storages/meow-memory/prompts/`）。

| 参数 | 类型 | 说明 |
|---|---|---|
| `target` | string | 省略 = 只查看当前目录、三个预设与切换开关；要切换则传预设标记或绝对路径 |

**默认行为（`security.allowHomeSwitch: false`）**：只能查询。传 `target` 会被**拒绝**并说明原因（"搬动目录会改变实例数据的落点，模型不应能搬走"）以及如何打开开关。这是 #64-2 的修复。

**打开 `security.allowHomeSwitch: true` 后**才允许切换：

| 标记 | 落点 |
|---|---|
| `default` | 平台用户主目录 |
| `dsh-storage` | `<DSH home>/storages/meow-memory` |
| `plugin-root` | `<插件根>/storage` |

切换行为：同盘移动 / 跨盘复制；**旧目录绝不自动删**；目标已有内容则直接启用、不覆盖；非法 `target` 不会误切。0.33 起全局数据目录里还包含**用户级全局记忆库**（`global/memory.db`），切换会连它一起搬；搬前会先关闭全局库连接（Windows 上打开的 SQLite 文件会阻塞 rename）。切换结果写在 `<DSH_HOME>/storages/meow-memory-home.json` 指针，跨重启生效。

> 若本机有多个 dsh 实例共享旧目录，切换后请同步修改它们的设置。

## 自动注入与手动工具的分工

- **注入**（首轮快照、每消息命中、压缩后重注入）受 `budget.*` 字符上限约束，且 **untrusted 库不注入**；0.33 起首轮快照的 soul/user/全局 rules 优先来自全局库（工作区库兜底），项目全景/重注入仍只读工作区库；0.35 启用语义后**每条用户消息会发一次 query embedding 请求**（LRU 仅救重复文本；失败静默回退词法，不影响注入）；
- **手动工具**（`memory_search` / `memory_project` / `memory_read` / `memory_list` 等）按调用返回，不受注入预算约束，但在 untrusted 库上会被**拒绝**（明确报错，不是返回空）；`dream` / 反思同样拒绝。读类工具两库并查（`memory_project` 除外）。启用语义后 `memory_search` 的 query 也会发一次 embedding 请求；写入类工具在启用时会**内联补该条 embedding**（best-effort）。
- `memory_list` 是唯一"看全库但不读正文"的低成本入口；`memory_forget` 是唯一删/归档入口（另有 `memory_update status=archived`，效果等价于归档）。

## 层级与子类目

| 层级 | 含义 |
|---|---|
| `soul` | AI 自身 |
| `user` | 用户基本信息与偏好 |
| `project` | 项目信息（带 `subcategory`） |
| `fact` | 原子事实 |
| `lesson` | 教训与纠正 |
| `topic` | 进行中的讨论话题（带目标句 `goal`） |
| `rules` | 设计原则与行为准则 |

`project` 的 `subcategory`：`overview` / `structure` / `decisions` / `quotes` / `ops` / `todo`。

**全局标记**：当前语言包 `labels.md` 的 `project.global` 值（中文包为「全局」，英文/葡语包为 `global`）。它随 `promptLang` 走——否则英文包里模型写的 `"global"` 会被当成一个叫 global 的项目。
